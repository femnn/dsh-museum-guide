# 博物馆导游辅助器

给一座博物馆，出一条能直接照读的讲解逐字稿：先定地图，再查资料，按展厅写，最后用确定性字数审核卡住下限。

## 它解决什么

写讲解稿最容易糊弄的三件事：不知道展厅顺序、只讲几件明星文物、字数靠空话凑。这个插件把三件事都变成可检查的记录：

- **地图先行**：没有记录导览图/展厅顺序，审核直接不通过。
- **逐厅成段**：每段有独立字数，哪个厅薄一眼看得出。
- **硬字数**：默认目标 22000 字、下限 20000 字，低于下限不通过，并给出「还差多少字」。

## 怎么用

1. 左侧栏点「博物馆导游」，在面板里填博物馆名与城市，点「建档」。
2. 点「复制启动指令」，把指令粘到会话输入框发送。会话里的 Agent 会按顺序：
   - 找官方导览图、参观手册、展陈平面，用 `museum_guide_map` 记录展厅顺序和 `floors`（一到几层、每层有哪些厅）；
   - 检索网页与小红书、抖音、快手、视频号的笔记/视频，用 `museum_guide_research` 记录来源和可用故事点；
   - 按展厅逐段写，用 `museum_guide_section` 写入；每写完一厅顺手搜这一厅的讲解视频，用 `museum_guide_video` 挂上（B站、小红书、抖音、快手、视频号，只挂真实链接）；
   - 用 `museum_guide_audit` 反复审核，不够就补写；
   - 用 `museum_guide_export` 导出 Markdown 终稿。
3. 回到面板：逐字稿、审核、资料、地图四个页签随时看进度；字数进度条上的细线就是 20000 字下限。

## 工具的八个动作

| 工具 | 作用 |
| --- | --- |
| `museum_guide_start` | 建项目，记目标与下限 |
| `museum_guide_map` | 记录导览图、展厅顺序、空间清单、楼层 `floors` |
| `museum_guide_research` | 记录一条资料（平台、链接、可用故事点、涉及展品） |
| `museum_guide_section` | 写入开场或某个展厅的正文（可同时带视频） |
| `museum_guide_video` | 给某一厅补挂讲解视频链接 |
| `museum_guide_audit` | 统计字数、展厅、展品覆盖，检查开场长度、结尾总结、互动设计 |
| `museum_guide_export` | 导出 Markdown 到数据目录 |
| `museum_guide_projects` | 列出已有项目，接着上次写 |

## 一句话跑完全程（技能）

装了同名技能 `museum-guide`（`~/.dsh/skills/museum-guide/SKILL.md`）：只要在会话里说「给XX博物馆写讲解稿」或直接报馆名，就会按「建档 → 找导览图与楼层 → 查网页/小红书/抖音/快手/视频号/B站 → 逐厅写 → 每厅挂视频 → 字数审核 → 导出」跑完。不用再手敲流程。

## 页面结构

打开面板先看到**参观路线**，第二个页签才是全文逐字稿。字数、展品覆盖、资料、检查项这些后台数据收在右上角「详情」按钮里，默认不显示。

左侧路线按真实参观顺序排列（01、02、03…），点任意一站，右侧立即显示这一站所有分篇的文字和视频，不用跳转、不用滚动查找。地图下面的「楼层平面图」可展开看每层的空间编号图。逐字稿页签里，整张卡片点任何位置都能展开/收起。

## 地图：按官方空间编号画

地图按楼层自上而下叠放（上 / 中 / 下），每一层里是官方空间编号（1、2、3…）。同一个展厅的不同篇章归在同一个空间块下面，例如「2 源起江南」下面挂「江海共潮生 / 手铲释天书 / 考古见姑苏（上）（中）（下）」，不再拆成一堆并列方块。点展厅名直接跳到对应逐字稿并高亮，带视频的显示 ▶ 数量。

### 编辑地图 / 手动添加博物馆

不用等 Agent，自己就能录：

- 面板左侧「手动录入地图」：填馆名后，按下面的格式写楼层和空间，保存即建档：
  ```
  一层
  1 序厅 = 序厅
  2 第一展厅 = 江海共潮生 / 手铲释天书
  负一层
  3 第二展厅 = 文明溯源 / 吴越新证
  户外
  7 户外展区 = 下沉广场
  ```
- 已有项目点「编辑地图」可以改同一份文本；
- 现场拍的官方导览折页/手册平面图，可以在编辑器里直接上传（png/jpeg/webp/gif，≤12MB），会显示在地图上方；也可以填官方图片链接。

`museum_guide_map` 的 `floors` 支持两种写法：`rooms[{no,name,halls[]}]`（推荐，带官方空间编号）或旧的 `halls[]`。没有 floors 时退回按 `zones[].floor` 自动分组。

## 本地语音（YoVoice）

面板阅读区有模型路径输入框（带 `~/.yovoice/models` 下 `.gguf` 的候选列表）和「用本地模型生成音频」。长厅会按 320 字左右分段合成，进度条与「第 N/M 段 · 已用秒数」实时更新；失败会直接显示原因（模型不存在、某段失败、引擎启动失败）。

生成结果缓存在 `~/.dsh/museum-guide/audio/`，同样的文字与模型不会重复生成。引擎复用：端口上已有同模型实例时直接复用，不重复加载。

配置项（`cordis.patch.yml`）：

- `ttsEnginePath`：`audiocpp_server` 路径，默认 `/Applications/yovoice.app/Contents/Resources/engine/audiocpp_server`
- `ttsModelDir`：模型目录，默认 `~/.yovoice/models`
- `ttsPort`：本地引擎端口，默认 49371（与 YoVoice App 自己用的端口分开）
- `ttsVoiceRef` / `ttsReferenceText`：自定义音色的参考音频路径与对应文字；填了就按这个音色生成

生成结果缓存在 `~/.dsh/museum-guide/audio/`，同样的文字与模型不会重复生成。

## 讲解视频

每一厅可以挂多条视频，记录平台、标题、链接和备注。面板的逐字稿卡片会显示「视频 n」和可点击的链接，展开后可见；导出的 Markdown 也会在每段末尾列出视频。只挂真实可打开的链接，搜不到就留空。

## 审核口径

- **字数**：去掉空白后的字符数，中文标点计入（与一般「字数」口径一致）；另给一个分词字数（汉字逐字 + 英文单词）。
- **下限/目标**：默认 20000 / 22000，可在设置或建档时改。
- **开场**：默认不超过 1300 字（约 5 分钟，按 240 字/分钟折算）。
- **结尾**：最后 600 字出现「总结 / 结语 / 综上 / 感谢聆听 / 谢谢大家」等收束词判为不合格——要求讲完最后一个展厅就停。
- **互动**：出现「互动 / 提问 / 请回答 / 举手 / 跟我念」判为不合格。
- **地图**：没有地图记录判为不合格。
- **展厅数**：少于 3 段判为不合格。

## 明确不做的事

- 面板不调用模型写稿：研究和写作由会话里的 Agent 用它的搜索与写作能力完成，面板负责记录、展示与审核。这样才能用上你在 DSH 里已经配好的模型和联网能力。
- 插件不内置小红书/抖音等平台的登录态，也不抓取需要登录的私有内容；检索通过搜索引擎索引与公开页面完成，遇到反爬会如实记「未取到」，不编造。
- 数字与史实以官方与权威媒体来源为准；讲解稿里的故事化表达可以有温度，但不改写文物定名、年代、出土地点这类硬信息。

## 数据位置

- 项目：`~/.dsh/museum-guide/projects/<id>.json`（可在设置里改 `dataDir`）
- 导出：`~/.dsh/museum-guide/exports/<id>-<馆名>.md`

## 配置

`cordis.patch.yml` 里的 `config`：

- `dataDir`：数据目录，留空用默认位置。
- `targetChars` / `minChars`：目标与下限字数。
- `introMaxChars`：开场字数上限。
- `charsPerMinute`：折算讲解时长，默认 240 字/分钟。
